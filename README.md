# 植保飞防作业台

以 Python 完整承接田块申报、处方审签、航段执行和证据归档，支撑药害投诉的追溯定责。

## 数据约定

- 坐标统一使用 WGS84，经纬度数组首尾闭合；剂量使用毫升每亩，距离使用米；
- 每个航迹点同时包含设备时间（`device_at`）和接收时间（`received_at`），离线期间产生的定位点允许稍后同步；
- 药箱编号代表一次装载事实，换箱后即使药剂相同也使用新的编号；
- 敏感区域的缓冲距离来自其自身类别；
- 处方一经审签即冻结：适用作物、药剂批次、安全间隔期不可再改，审签签名可核验。

## 参考资料

`reference/domain.json` 集中维护田块边界、敏感区域、禁飞区、药剂标签、作业条件上限和三组航迹：

- `track_points`：离线航迹样例一（原任务 TASK-0907-A，含越界、时间倒退、异常剂量、换箱）；
- `reflight_track_points`：离线航迹样例二（补飞任务 TASK-0907-B）；
- `late_track_points`：迟到补传点，其中 P-18 的后到版本与已归档内容冲突。

## 作业流程

1. **田块申报**（`declaration.py`）：登记田块边界、敏感区域、禁飞区、药剂标签，校验闭合性、作物一致性；
2. **处方审签**（`prescription.py`）：起草 → 审签 → 冻结，目标剂量必须落在标签范围内，审签后不可再改；
3. **航段执行**（`execution.py`）：任务拆分为航段；风速或降雨越过作业条件时，未起飞航段自动失效，已起飞航段记录返航决定；补飞任务承接原任务的失效航段，证据链独立；
4. **证据归档**（`evidence.py`）：航迹按批次同步入库——
   - 同一批次重复同步直接忽略，不同批次同名点按点去重，**重复同步不会多算用药量**；
   - 同名点内容冲突时保留先到版本，后到版本记入冲突清单，**后到数据不能悄悄改写原结论**；
   - 越界片段、禁飞区侵入、缓冲带侵入、时间倒退、异常剂量按类别单独成项；
   - 每接受一批新点，证据修订号加一，各修订号快照独立保存；
5. **可校验摘要**（`summary.py`）：摘要内容做规范化序列化后取 SHA-256，重复导出结果一致；新修订号的摘要记录 supersedes 与逐条变更对照，旧摘要原文保留、可随时核验；
6. **投诉追溯**（`complaints.py`）：从一次投诉追到审核人、每个航段覆盖面积、换箱节点（含批次）、邻近敏感区距离和分项异常，原任务与补飞任务分链呈现。

## 运行

端到端演示（摘要与追溯报告写入 `out/`）：

```bash
python3 -m sprayops
```

资料自检与行为测试：

```bash
python3 -m unittest discover -s tests
```

摘要核验：

```python
from sprayops.summary import load_summary, verify_summary
verify_summary(load_summary("out/summary_TASK-0907-A_r2.json"))
```
